# 论文实验协议判别与步骤规划

PDF 通用路线分开处理仓库定位、实验判别、步骤编译和运行后验收。仓库定位阶段不会要求完整数据集、软件依赖或实验数值。PaperReader 从全 PDF 的代码声明、脚注和 GitHub 链接提取所在位置；RepositoryVerifier 阅读实际 PDF 证据与固定 Git README/引用/目录，确认论文与仓库关系。自动确认失败后，可以由用户为同一 PDF 补充仓库，来源和作者身份分别记录。

确认仓库后，ExperimentProtocolAgent 阅读完整论文和有界源码，选定一个完整的论文实验。输出包括：

```mermaid
flowchart LR
    A[论文全文与固定作者仓库] --> B[识别完整实验协议]
    B --> C[补读缺失源码并校验来源]
    C --> D[编译命令、数据、依赖与捕获规则]
    D --> E[程序核验与独立语义审查]
    E --> F[冻结计划并执行完整作者实验]
    F --> G[重载所选模型并独立评估全部重复]
    G --> H[按冻结参考值判定数值达标]
```

论文中的实验方法、实验设置、附录、结果表与作者脚本共同定义协议，不能只从摘要推测步骤。PaperReader 和阅读验证器都覆盖完整的提取文本；仓库定位也不再只读首页和关键词附近。长论文按连续范围分批，边界保留上下文，记录全文哈希、范围、已读字符数及批次完成数。单批输出过密或被模型截断时自动拆小后重读，失败响应不计入已读范围；不会为符合输出窗口而删除论文内容。全部批次返回有效、有真实片段 ID 的笔记后才能汇总，汇总失败仍停止。笔记只是导航，后续协议和数值检查仍引用实际 PDF 页面与固定源码。很长的笔记分层汇总时保留全部原文引用，原始逐批笔记始终保留。

单次上下文和输出窗口限制请求大小，不构成全论文阅读调用次数的预算。正文、结果表、参考文献和附录均须经过阅读；阅读完成与实验规划、训练完成、数值达标分别判定。报告列出实际覆盖字符及完成批次数，阅读未完成不能通过质量审查。

逐批阅读笔记随后进入实验判别来源包。程序重新检查 PDF 哈希、全文字符哈希、连续覆盖范围和笔记引用的实际原文，再把字符位置映射为当前 PDF 页片段 ID。判别器可利用笔记定位主表与附录的不同协议，但不能把笔记当作原文证据，也不能接受另一 PDF 或覆盖不完整的笔记。

源码目录完整保留，但有界初始阅读不等于已读完仓库；判别 Agent 可以在冻结前补读源码两轮，每轮最多八个目录内文件。NPZ 划分摘要另有独立两轮，每轮八个路径，避免源码补读耗尽所选数据的数值核验机会；混合请求同时计入两项。读取内容必须与固定版本哈希一致，并写入来源包。重复读取是幂等操作，仍计入相应预算；非法或超预算请求不能无限循环。可读源码目录单独列出精确路径及已读状态，NPZ 目录列出摘要是否可用；初始阅读优先作者入口、实验命令脚本和配置。按需 NPZ 摘要严格检查哈希、压缩与展开大小、数组类型及 mask 数量，禁止 pickle；读取或总摘要容量检查失败不修改来源包。不存在的文件不会被猜测或自动替换；反馈给出具体路径错误。真实冲突和信息不足的判定不重试为另一实验。

| 内容 | 必须确定的关系 |
| --- | --- |
| 方法 | 论文方法及变体与实际模型对应，不能混用基线或另一变体 |
| 数据 | 数据集、原始划分、预处理与实际加载器对应 |
| 训练 | 优化器、参数、轮数和提前停止规则来自真实来源 |
| 模型选择 | 最佳验证轮次、最后一轮或其他作者规则，以及实际保存/恢复并评估的权重 |
| 重复 | 论文的完整运行/划分次数及汇总方式，不能用一次结果代替均值 |
| 评估 | 指标定义、单位、表格行列及参考值属于选定实验 |
| 实现 | 真实作者入口、工作目录、命令参数和设备要求 |

每一项引用程序提供的原文片段 ID。程序展开真实页码、文件、原文和哈希，不要求模型重新抄写 PDF 的换行、连字或 Markdown 列表符号。数值字符串可规范成数字，但仍须由原文支持；版本、指标数值和单位不会被近似匹配。普通文件目录证据只能证明存在，NPZ 划分摘要由程序直接读取，0/1 整数 mask 与布尔 mask 均记录实际选中数量。

大型划分目录只先列出完整路径，选定实验后按需读取实际数组，避免把数百个无关数据集的数字塞进上下文。短而稳定的来源 ID 与文件路径分别提供，减少同名入口路径/哈希被模型拼错的机会，仍须精确引用。补读反馈明确列出已满足的请求、可引用的实际 ID 和剩余轮次，不因修正引用而重新请求相同划分。训练参数在实验判别阶段就与真实作者命令及 argparse 默认值对账；原文某处出现一个数字不证明它是该参数的值。

参数解析发现固定目录内的某个导入文件尚未读入时，程序按真实导入路径补读并重新检查同一协议，不要求模型猜文件名或额外调用模型。这与 Agent 请求共享源码两轮及容量限制，哈希或容量检查失败仍停止；源码及被拒绝的规划证据不会因持久化异常而丢掉原始拒绝理由。

实验协议通过结构与证据检查后，步骤规划器编译该实验，不能改换命令、设备、关键参数、重复次数或参考指标。实际 argparse 默认值和命令覆盖由程序解析，布尔开关未设置时的默认值也有源码依据；不会要求模型在运行命令里抄出并不存在的 False 字面量。依赖通过选定入口的实际源码导入链解析，包括包初始化、子模块及父层相对导入；未使用的模型提议包记录并排除。动态 argparse 类型、复杂 action 或 nargs 等当前不能确定编译的形式明确报告能力缺口。未知条件分支的外部依赖保守保留；冻结 CPU、隐藏 CUDA 且原生运行前检查通过时，可以排除未见 torch 重绑定的源码中精确 `if torch.cuda.is_available():` 分支，保存该分支原文与哈希。CUDA、复杂条件、别名、可见重绑定或动态 exec 等不使用此排除。作者代码始终原样执行，运行时异常仍拒绝。仍需独立审查完整论文与源码的语义关系；有来源的数字不自动证明参数或表格对应关系正确。

论文与代码冲突或信息不足时，判别器可以仅输出拒绝理由及其论文、仓库来源，不要求填满无法确定的正向协议字段。已核对来源的负向判定直接停止，并保存分类与证据；不能为了满足 JSON 格式而补造参数、次数或参考值。

2026-10-11 的真实 API 回归使用已退役的 GCNII PDF 和固定作者源码：针对仓库位置的阅读审查、作者关系核验、完整实验协议判别、步骤编译及六项独立语义检查通过。选定的是 full-supervised Cora 的完整十次原生划分实验，1500 轮上限及原始提前停止规则，论文参考 88.49%。此记录只证明识别和规划的回归，不是论文训练或最终新 PDF 验收。

语义审查有七项：同一实验、完整作者训练协议、模型选择与实际评估权重、完整数据与测试划分、实际测试数据捕获、指标与论文参考对应、依赖兼容性。LLM 对每项说明证据，程序核对结构、引用和来源后按所有必要项的逻辑与汇总判定，不使用模型另写的总 verdict。旧式返回中相互矛盾的总 verdict 会保留为审计记录；任何真实失败或证据缺失仍拒绝。真实语义拒绝不会触发调参。

训练结束与模型选择分别判别。最佳验证分数的标量不等于该轮模型；如果作者只保留分数却未保留或恢复对应权重，不能用最终轮模型替代独立评估，也不能按测试集表现选模型。模型选择字段引用实际定义规则的源码；论文未描述保存/恢复细节时不强制补造 PDF 引用。独立模型选择审查仍必须同时引用论文实验上下文和源码，证明每次重复的捕获模型与报告测试结果对应。引用和结构检查不会自动证明这项语义判断正确，运行后仍需要真实模型和独立指标核验。

对已识别的论文百分比划分声明，程序额外读取所选真实 NPZ 的 train/val/test 掩码，检查互斥、完整覆盖及实际数量，不根据文件名推断比例。按类划分时，从带明确 node_id/label 表头的完整标签文件读取每类样本并逐类核对；只容许固定的整数舍入范围，不使用可调百分比容差。冲突保留原文、实际数量、标签和掩码哈希，直接停止规划，不能靠另一次 LLM 审查覆盖或改换实验。未识别的声明或数据格式记录 not_checked，仍需要语义核验，不声称已完成程序化比例验证。

新增模型选择后的真实 API 回归中，模型为退役 GCNII 的 Cornell 完整十次实验返回了七项通过，但声称作者掩码符合论文的每类 60%/20%/20% 划分。实际程序读取 183 个节点的掩码，发现 train/val/test 为 87/59/37；逐类数量也超出舍入范围。新增数值检查明确拒绝这一论文/源码冲突，原始模型提案经过真实规划编译后同样停止在 partition_validation，未重试、未训练。这说明先前规划通过只能证明审查返回通过，不能单独证明计划正确；该论文仍是退役回归样本，最终新 PDF 验收未完成。

失败结果记录 `failure_phase` 和 `failure_kind`：`protocol_conflict` 表示论文与源码冲突；`missing_information` 表示证据不足；`model_structure_error` 表示模型结构输出错误；`runtime_unsupported` 表示依赖超出已验证运行环境；`protocol_mismatch` 表示独立语义审查未建立协议对应；`invalid_evidence` 表示引用或数值证据无效。没有错误文本的异常也保持 ERROR，不能因为空字符串误显示 COMPLETED。

冻结计划后执行原始作者入口，观察实际训练更新和完整测试集。稀疏 COO/CSR 输入通过其实际索引和值导出，不转成替代稠密算法。独立进程重载每个真实模型，重新推理并计算指标。所有原生重复、进程完成、协议与数值门槛共同决定结论。

原生模块级 `for` 重复循环也可观察：循环计数器必须按 0 到 N−1 顺序运行，验证选择必须是唯一的标识符比较分支，结果必须直接赋值。程序在原始赋值完成后保存实际模型、输入、标签和测试索引，完整迭代回到原始循环边界时再确认更新数。作者入口整体正常退出、全部重复及优化器更新对账后，才写成功捕获记录；少跑、多跑、计数不符或训练后的异常都不能产生成功记录。最终权重不覆盖验证所选权重。快照及导出保存和恢复 Python、NumPy、PyTorch CPU/CUDA 随机数状态，避免改变后续作者初始化。复杂选择表达式和其他循环形式目前明确不支持。

独立评估步骤显式依赖全部作者步骤，并要求捕获记录和全部模型/张量产物存在。结果记录进程退出、完整训练和测试捕获、全部重复评估、新进程预测核验、作者指标对账及论文数值达标六项完成检查。最后一项可为 false，此时结论为实验完成但参考值未达到。报告列出每一阶段的完成依据；这些运行后检查不能由 LLM 的通过声明代替。

新增有界源码阅读、模块级快照、随机数不干扰与结束判定均由构造样例进行机制回归；这些测试不构成真实新 PDF 的完整复现验收。GoogleDriveDownloader 0.4 的纯 Python wheel 已检查并进行真实导入测试，其遗漏声明的 requests 依赖以 2.32.3 单独冻结；不能因此声称任意 Google Drive 数据下载已验证。

2026-10-11 的独立 ACM-GNN PDF 首次网页验收通过阅读、资源定位及仓库关系核验，实验判别因补读路径/引用问题失败，训练未启动，该 PDF 已退役。使用它进行全文阅读的真实 API 回归时，模型先出现输出容量不足；自动拆批后连续覆盖全部 127,204 个提取字符，5 批均完成，独立原文审查通过。另一次实验规划回归仍因引用 ID 混淆及重复补读请求被拒绝；不能将全文阅读通过等同于规划正确或复现成功。

后续退役样本回归通过补读和协议结构检查后，仍在编译时发现模型写出的 layers 参数与实际作者命令/default 不一致，未启动训练。该参数对账已前移至实验判别阶段；构造样例验证，即使错误参数值恰好出现在 seed 等其他源码位置，也必须拒绝。退役样本回归不构成新 PDF 的完整复现验收。

作者使用短参数别名或必填参数时，按实际 argparse 声明解析；省略必填参数会在训练前拒绝。独立捕获支持固定的字典/列表键路径，如 `{name:"idx_all",keys:["valtest"]}`，不执行表达式或切片。作者的完整整数 NumPy 标签可以无损保存为整数 tensor；浮点标签不能通过取整混入评估。若作者 forward 已按测试索引返回测试行，计划必须声明 `output_alignment="selected_test"`，并把同一个完整测试选择器作为 forward 参数；评估只索引标签，避免再次索引已选出的模型输出。原始整数索引、标签顺序及完整样本数仍被验证。

目前通用执行支持 PyTorch 分类任务、完整作者原生入口和原生重复循环；未覆盖任意训练框架或任意指标。超出能力时说明缺少的条件，不声称已完整复现。已用于修复的 PDF 只能用于回归，最终验收仍需冻结后获取的新论文。
