# 论文实验协议判别与步骤规划

PDF 通用路线分开处理仓库定位、实验判别、步骤编译和运行后验收。仓库定位阶段不会要求完整数据集、软件依赖或实验数值。PaperReader 从全 PDF 的代码声明、脚注和 GitHub 链接提取所在位置；RepositoryVerifier 阅读实际 PDF 证据与固定 Git README/引用/目录，确认论文与仓库关系。自动确认失败后，可以由用户为同一 PDF 补充仓库，来源和作者身份分别记录。

确认仓库后，ExperimentProtocolAgent 阅读完整论文和有界源码，选定一个完整的论文实验。输出包括：

| 内容 | 必须确定的关系 |
| --- | --- |
| 方法 | 论文方法及变体与实际模型对应，不能混用基线或另一变体 |
| 数据 | 数据集、原始划分、预处理与实际加载器对应 |
| 训练 | 优化器、参数、轮数和提前停止规则来自真实来源 |
| 模型选择 | 最佳验证轮次、最后一轮或其他作者规则，以及实际保存/恢复并评估的权重 |
| 重复 | 论文的完整运行/划分次数及汇总方式，不能用一次结果代替均值 |
| 评估 | 指标定义、单位、表格行列及参考值属于选定实验 |
| 实现 | 真实作者入口、工作目录、命令参数和设备要求 |

每一项引用程序提供的原文片段 ID。程序展开真实页码、文件、原文和哈希，不要求模型重新抄写 PDF 的换行、连字或 Markdown 列表符号。数值字符串可规范成数字，但仍须由原文支持；版本、指标数值和单位不会被近似匹配。普通文件目录证据只能证明存在，NPZ 划分摘要由程序直接读取，0/1 整数 mask 与布尔 mask 均记录实际选中数量。

实验协议通过结构与证据检查后，步骤规划器编译该实验，不能改换命令、设备、关键参数、重复次数或参考指标。实际 argparse 默认值和命令覆盖由程序解析，布尔开关未设置时的默认值也有源码依据；不会要求模型在运行命令里抄出并不存在的 False 字面量。依赖通过选定入口的实际源码导入链解析，包括包初始化、子模块及父层相对导入；未使用的模型提议包记录并排除。动态 argparse 类型、复杂 action 或 nargs 等当前不能确定编译的形式明确报告能力缺口。导入扫描保守保留条件分支中的外部依赖，不声称已经证明每个分支可达。仍需独立审查完整论文与源码的语义关系；有来源的数字不自动证明参数或表格对应关系正确。

论文与代码冲突或信息不足时，判别器可以仅输出拒绝理由及其论文、仓库来源，不要求填满无法确定的正向协议字段。已核对来源的负向判定直接停止，并保存分类与证据；不能为了满足 JSON 格式而补造参数、次数或参考值。

2026-10-11 的真实 API 回归使用已退役的 GCNII PDF 和固定作者源码：针对仓库位置的阅读审查、作者关系核验、完整实验协议判别、步骤编译及六项独立语义检查通过。选定的是 full-supervised Cora 的完整十次原生划分实验，1500 轮上限及原始提前停止规则，论文参考 88.49%。此记录只证明识别和规划的回归，不是论文训练或最终新 PDF 验收。

语义审查有七项：同一实验、完整作者训练协议、模型选择与实际评估权重、完整数据与测试划分、实际测试数据捕获、指标与论文参考对应、依赖兼容性。LLM 对每项说明证据，程序核对结构、引用和来源后按所有必要项的逻辑与汇总判定，不使用模型另写的总 verdict。旧式返回中相互矛盾的总 verdict 会保留为审计记录；任何真实失败或证据缺失仍拒绝。真实语义拒绝不会触发调参。

训练结束与模型选择分别判别。最佳验证分数的标量不等于该轮模型；如果作者只保留分数却未保留或恢复对应权重，不能用最终轮模型替代独立评估，也不能按测试集表现选模型。模型选择字段引用实际定义规则的源码；论文未描述保存/恢复细节时不强制补造 PDF 引用。独立模型选择审查仍必须同时引用论文实验上下文和源码，证明每次重复的捕获模型与报告测试结果对应。引用和结构检查不会自动证明这项语义判断正确，运行后仍需要真实模型和独立指标核验。

对已识别的论文百分比划分声明，程序额外读取所选真实 NPZ 的 train/val/test 掩码，检查互斥、完整覆盖及实际数量，不根据文件名推断比例。按类划分时，从带明确 node_id/label 表头的完整标签文件读取每类样本并逐类核对；只容许固定的整数舍入范围，不使用可调百分比容差。冲突保留原文、实际数量、标签和掩码哈希，直接停止规划，不能靠另一次 LLM 审查覆盖或改换实验。未识别的声明或数据格式记录 not_checked，仍需要语义核验，不声称已完成程序化比例验证。

新增模型选择后的真实 API 回归中，模型为退役 GCNII 的 Cornell 完整十次实验返回了七项通过，但声称作者掩码符合论文的每类 60%/20%/20% 划分。实际程序读取 183 个节点的掩码，发现 train/val/test 为 87/59/37；逐类数量也超出舍入范围。新增数值检查明确拒绝这一论文/源码冲突，原始模型提案经过真实规划编译后同样停止在 partition_validation，未重试、未训练。这说明先前规划通过只能证明审查返回通过，不能单独证明计划正确；该论文仍是退役回归样本，最终新 PDF 验收未完成。

失败结果记录 `failure_phase` 和 `failure_kind`：`protocol_conflict` 表示论文与源码冲突；`missing_information` 表示证据不足；`model_structure_error` 表示模型结构输出错误；`runtime_unsupported` 表示依赖超出已验证运行环境；`protocol_mismatch` 表示独立语义审查未建立协议对应；`invalid_evidence` 表示引用或数值证据无效。没有错误文本的异常也保持 ERROR，不能因为空字符串误显示 COMPLETED。

冻结计划后执行原始作者入口，观察实际训练更新和完整测试集。稀疏 COO/CSR 输入通过其实际索引和值导出，不转成替代稠密算法。独立进程重载每个真实模型，重新推理并计算指标。所有原生重复、进程完成、协议与数值门槛共同决定结论。

作者使用短参数别名或必填参数时，按实际 argparse 声明解析；省略必填参数会在训练前拒绝。独立捕获支持固定的字典/列表键路径，如 `{name:"idx_all",keys:["valtest"]}`，不执行表达式或切片。作者的完整整数 NumPy 标签可以无损保存为整数 tensor；浮点标签不能通过取整混入评估。若作者 forward 已按测试索引返回测试行，计划必须声明 `output_alignment="selected_test"`，并把同一个完整测试选择器作为 forward 参数；评估只索引标签，避免再次索引已选出的模型输出。原始整数索引、标签顺序及完整样本数仍被验证。

目前通用执行支持 PyTorch 分类任务、完整作者原生入口和原生重复循环；未覆盖任意训练框架或任意指标。超出能力时说明缺少的条件，不声称已完整复现。已用于修复的 PDF 只能用于回归，最终验收仍需冻结后获取的新论文。

2026-10-11 的后续独立样本 DropEdge 在网页阅读审查阶段失败：原文首页已有 “Codes are released on” 声明，但旧的单数关键词规则没有标记该声明，PaperReader 的后处理又把真实 PDF 候选覆盖成“未找到”。两个审查轮次均拒绝，训练未启动，终态无活动进程。修复后，词法标记只影响候选排名；实际非参考文献 PDF 链接保留其页码与上下文并标为未确认候选，作者身份仍交给固定 Git/PDF 联合审查。补齐复数代码/实现声明及基线排除，105 项相关测试通过；退役 DropEdge 的真实 API 阅读和资源定位回归也通过。此记录不构成新 PDF 完整复现成功。
