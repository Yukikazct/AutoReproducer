# Windows 适配与入口一致性跟进（2026-10-21）

当前支持与验收目标为 Windows x64、CPython 3.11 / 3.12。本轮先处理能直接影响入口真实性、下载和取消的工程缺口；不新增 macOS 适配，也不将回归测试当作论文复现验收。

## 本轮实现

- 未匹配预设的真实标题走论文分析与仓库发现，完整保留候选，然后明确请求原始 PDF。未取得正文时不下载作者源码、不构建环境、不生成替代代码执行；报告记录 `needs_pdf`、未运行及下一步。
- 仅有候选的报告不再声称已经取得固定版本作者源码，也不列出尚未准备的“官方仓库执行命令”。网页同时显示补充 PDF 的提示。
- 网页 Docker 控件固定关闭，所有当前网页入口使用本地受控进程；优化提示与现有关闭状态一致。
- 数据集与权重下载统一使用 `run_owned_process`，获得同一套 Windows 所属进程清理和容错输出解码。Python 下载脚本使用当前解释器与独立参数启动，支持中文、空格路径和 `.PY` 后缀，不依赖 Windows 文件关联。
- 新增真实下载、非 UTF-8 诊断、取消下载器及其子进程的回归。Windows 专项通过独立控制台向任务发送真实 Ctrl+Break，核对中断状态、原始输出文件、所属训练进程结束及文件锁可重新取得。
- README 统一使用 Windows PowerShell 和虚拟环境解释器；[当前架构](current_architecture.md) 按实际入口与调用链说明模块职责及能力边界。
- 普通真实 PDF 新增可选 `strict_validation`，默认关闭，保留直接执行作者代码的路径。请求严格核验时检查冻结的来源、实验协议和计划，并接入完整执行与独立新模型推理、指标复算；资格证据不足或当前不支持时保存 `unavailable` 及具体原因，继续普通作者运行及报告中的参考比较。
- 网页只对普通真实 PDF、无预设和语料对照时显示严格核验勾选项；标题、固定预设、Mock 和语料入口不会继承残留选择。请求经后台线程与独立 worker 透传，旧缓存后端按 API 版本升级；旧审核和优化开关仍关闭。
- 严格协议分析器会在冻结源码内自动跟随程序解析出的确切本地 import，逐个核对源文件哈希，并受总文件数和字节预算约束；自动读取不消耗模型的两轮源码请求额度。达到证据上限仍记录具体原因，不能为单篇论文绕开边界。
- 严格捕获沿用全部原作者步骤，并将它们的 `timeout_s` 设为 `None`，不因规划器估时而截断原实验；追加的独立模型推理与指标复算步骤单独保留 300 秒上限。
- 严格准备失败时单独保留拒绝来源包，普通规划恢复到严格尝试之前的来源视图，使用自身的有界读取额度；严格补读不会挤占普通规划预算。恢复前仍检查源码和 PDF，冻结输入变化始终终止，不能当作环境故障换仓库重试。

## 显式源码兼容修复入口

普通真实 PDF 的网页新增默认关闭的“兼容性源码修复：失败后自动重试”，经后台线程及独立 worker 传递 `source_repair` 与精确 Python 白名单。白名单要求 1–32 个固定作者源码中已存在的 `.py` 相对路径，不接受目录、通配符、数据、评测或权重；标题、Mock、语料对照、外部代码和固定预设不进入此入口。该选项与严格核验互斥，网页切换时关闭另一项，服务请求同时启用时拒绝执行。

原命令真实失败后，服务复用该失败诊断，从固定源码与冻结输入建立独立修复副本，仅进入一次最多两轮的会话；每轮最多修改三个文件，拒绝候选也计入轮数。原作者工作区、冻结计划、来源及观测器保持独立，候选使用原 argv、cwd、步骤环境与已经准备的解释器及依赖，重跑全部原命令。安装失败、未运行、成功、取消、超时和 Notebook 计划不触发源码补丁。

提案和 diff 落盘后、应用前，除路径、摘要、语法和受保护文件检查外，还比较原/候选 AST。变量、字面量、运算、控制流、import、函数参数与训练/划分/评测敏感名称必须保留，仅允许同结构的 API/方法/关键字名称兼容改动；被替换原名须来自会话实际观测的缺失属性或意外关键字参数诊断。第二轮累积原失败及最新失败依据，前验不通过时不执行候选。此有界规则不构成任意程序的语义等价证明。

复制和内存快照前用 `stat()` 检查 **4096 文件 / 256 MiB** 上限；超限记录 `resource_limit` 并保留原失败。候选失败、取消或后验冻结输入/源码核对异常时整体恢复，无法完成回滚则记录 `rollback_failed` 并停止。修复记录沿用 Windows 扩展路径与 symlink / junction 拒绝边界。

`original_execution.json`、`source_repair.json`、独立执行计划、逐轮提案 / diff / 命令日志 / 回滚记录及 `source_repair_manifest.json` 绑定原来源、批准修改和实际源码摘要；服务另尝试生成上限 64 MiB、带脱敏成员摘要的证据 ZIP，报告附件与网页下载按 ZIP 哈希核对，生成失败保留诊断和运行目录原件。修复成功只确认补丁源码的原命令完成，以 `patched_author_repository`、`patched_author_code_execution`、`source_modified=true` 标记；保持 `paper_metrics_verified=false`、`is_reproduced=null`、`training_observed=false`。后续参考比较标记 `patched_author_output` 并携带清单摘要。完整边界见 [显式仓库兼容修复](repository_repairs.md)。

新增入口单独完成最终冻结源码专项 **248 passed / 0 skipped / 0 failed**。源码指纹为 `70687201756980b1a76ff64eb4162bd16483f772d534be6bdd3c2e81588c7770`，包含 Streamlit AppTest 控件、后台请求透传、真实子进程两文件修复、两轮不同错误、协议改动前拒绝、取消/复制异常、回滚、脱敏和报告下载。两项原生服务成功用例分别直接调用服务与经过网页后台；均保留原源码和 argv，修复清单及完整日志随报告归档。7 份清理记录全部 `released`、无剩余和错误，最终检查无命令行包含本次验收目录的 Python 进程。

另有周边回归 **1766 passed / 80 skipped / 0 failed**；该批早于最后的报告附件长路径修改，不能替代最终源码专项。跳过项不计为通过。最终专项中的模型回复和网络来源使用合成 fixture，真实执行由所属 Python 子进程完成；AppTest 控件测试与实际后台执行测试分开进行，尚无本轮真实模型 API / 外部论文的完整网页验收。来源、测试 XML、日志、逐文件摘要和两份修复运行证据见 [issue20_web_repairs_20261021.json](evidence/issue20_web_repairs_20261021.json) 与 [日志包](evidence/issue20_web_repairs_20261021_logs.zip)。
