# 显式仓库兼容修复

`RepositoryRunner.run_with_repairs()` 在调用方提供的隔离源码副本上，尝试修复实际运行失败。默认的 `run()`、网页 PDF 作者代码路线和固定预设不启用此入口，不改变原作者代码直接执行的约定。

调用方必须先导出独立、可丢弃的工作区，并明确列出可修改的源码。带 `.git` 的仓库目录不能作为修复工作区；共享源码缓存、应用目录和用户原始仓库不能用于候选执行。开始、应用和回滚时，工作区所属进程必须已结束。

```python
from src.llm.llm_client import LLMClient
from src.repository_runner import RepositoryRunner

runner = RepositoryRunner()
result = runner.run_with_repairs(
    workspace,
    original_steps,
    original_environment,
    llm=LLMClient(),  # 从已有环境配置读取 API 设置
    editable=["models/network.py", "train.py"],
    max_rounds=2,
)
```

## 候选、重跑和恢复

只有原命令实际执行并失败时才请求模型。环境准备失败、正常退出、取消和超时不触发源码修复。每个任务最多请求两轮；空补丁表示当前约束下无法修复，会提前停止。

模型获得 traceback、原命令和受限的真实源码上下文。响应包含修复理由与一至三个完整 UTF-8 文件替换，每个文件必须携带其 `path`、精确 `base_sha256` 和 `content`。未提供给本次模型的文件不能修改。命令、依赖和环境不接受模型改写。

每个候选的全部文件先统一检查：路径与链接、保护规则、重复目标、文件大小、原文件摘要和 Python 语法。任一文件不合法时全部不应用；执行前还拒绝已有本地生成代码检查器能够识别的命令执行、动态执行和网络外联等危险构造。检查器是确定性拦截措施，不是操作系统沙箱。

全部通过后先保存工作区快照，再应用候选，并清除受影响 Python 模块的旧字节码，避免同尺寸且同时间戳的修改仍执行旧代码。为避免复用此前步骤的过期结果，当前实现从头重跑原命令计划，保留原依赖关系、参数、时限和环境。

候选失败、取消、执行器异常或应用中途出错时恢复整个快照，包括其他被运行过程改动或删除的文件，并删除新产物。成功退出后还会核对原有受保护文件的摘要；修改数据、划分、评测等受保护输入也会拒绝并回滚。无法完成恢复时立即停止，不尝试下一候选，并明确标记 `rollback_failed`。

成功候选保留在隔离工作区。调用方应审查 diff 并按原实验协议验证结果；文件保护和命令正常退出都不能证明算法语义、完整实验协议或论文数值已经核验。因此此入口不能直接把结果标为论文复现成功，也不替代 #41 的独立核验。

## 证据与限制

每轮修复理由、脱敏提案、逐文件 diff、完整命令日志位置、执行结果和回滚记录保存在工作区外的 `.autorepro_repository_repairs/<id>/`；摘要为 `repairs.json` 和 `repair_report.md`。失败候选的日志不会被工作区回滚删除。API key 不进入提案或报告；带敏感内容的源码不发送给模型。

当前只支持替换已存在的普通 Python 源文件，不支持新增、删除、移动文件或修改评测、数据及权重。整个工作区快照保存在内存中，调用方应使用规模受控的源码工作区，不应把大型数据或模型缓存直接放入待快照树。本入口尚未接入网页自动修复；#20 的产品入口验收继续保持开放。
