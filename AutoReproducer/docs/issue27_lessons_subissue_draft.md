# [P2] 从论文复现中提炼科研认识与工程经验：LLM 证据总结

> 待前置验收通过后创建正式 GitHub 子 issue，并通过 GitHub 父子关系关联 #27。

## 目标

在已完成的论文复现之后，回答“我们从这次复现中学到了什么”，同时面向科研认识和工程经验。LLM 基于本次可追溯证据生成分析与下一步验证建议。

本 issue 是 #27 的正式子 issue。前置验收与对应运行：待 #27 的独立真实验收通过后填写运行 ID、提交和证据链接；当前不作为已发布或已验收功能。

## 触发与数据流

- 原作者进程结束，报告、日志、结构化结果和清理回执已保存，训练环境释放后，自动生成一次复现总结。
- 复用当前配置的 LLM；读取已归档证据，不重新安装实验依赖、不重新运行训练。
- 输入包含原 PDF 与固定作者源码、实际命令和参数、最终均值/标准差/次数、论文指标对比及限制、真实失败/修复记录和实测资源开销。
- 以运行 ID 和证据摘要保证自动生成幂等；历史查看、重连和报告下载不调用模型。模型失败单独记录，用户显式重试生成新的总结修订，原结果保留。

## LLM 的职责与证据要求

1. 科研认识：解释方法思想、本次结果支持什么、实验设置差异、适用边界，以及尚未回答的问题。
2. 工程经验：只总结真实发生的依赖、数据、运行、修复和成本问题，明确测量值、来源和适用条件。
3. 每条内容区分“论文陈述”“本次观察”“待验证假设”，关联 PDF 页码/原文、固定源码或实际日志/指标记录。程序校验证据引用，不把模型推断当作已验证事实。
4. 下一步建议包含研究问题、假设、拟改变因素、评价指标和预期观察，全部标记待验证。首版不自动执行后续实验、不改模型或实验协议。
5. 单次观测不支持因果结论；没有消融或独立验证时，不宣称已证明某机制或取得改进。缺少证据应明确写未知。

## 产物与界面

- 每个运行保存独立的 reproduction_lessons.json，记录输入证据摘要、生成状态、LLM 调用/版本信息与经校验的总结；新增 data.reproduction_lessons 独立展示总结状态。
- 通过报告修订机制增加“本次复现学到了什么”章节，分别展示科研认识、工程经验、限制和待验证建议，保留原始报告与运行证据。
- 网页、历史恢复、Markdown、ZIP 使用同一份保存的总结修订；生成期间可监控状态。
- 总结失败不改变原训练成功/失败、指标或论文对比结论；证据不足的总结不能写入 ExperienceStore 的已验证优化经验。

## 验收

- [ ] 使用 #27 本次真实验收运行的归档证据，通过真实 LLM 生成有引用的科研与工程总结。
- [ ] 覆盖成功、指标未达参考、设置不对应、运行失败和部分证据缺失；明确保留失败和未知。
- [ ] 无依据的事实、伪造引用或未执行实验结果不能作为“本次观察”输出；合理推断保留为待验证假设。
- [ ] 验证未自动启动后续实验、未改变参数/切分/指标，未把建议写入已验证经验。
- [ ] 模型超时、无 API、非合法响应不损坏原始结果；自动生成有界且同一输入不会重复调用。
- [ ] 浏览器刷新、应用重启后的历史恢复、Markdown 与 ZIP 一致；已有总结可在不调用 API、无训练环境时读取。
- [ ] 核对生成前后原始报告、日志、源码和运行结果摘要不变，训练环境及依赖保持已释放。
