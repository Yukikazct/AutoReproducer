## 通用行为

混合选择器采用有序固定路径，例如 `{name:'dataset',path:[{attribute:'graph'},{key:'node_feat'}]}`。旧字符串、`attributes` 和 `keys` 保持兼容，最多八步；完整路径必须存在于冻结源码 AST。运行时只读直接存储字段和内建容器，拒绝属性 getter、自定义索引、表达式和动态键。

整数 `[N,1]` 标签在捕获与独立评估中无损展平；不修改作者训练输入。模型张量文件保留原始标签字节、dtype、字节序、形状与摘要，独立进程重建并校验转换。浮点、多列、溢出、越界及样本错位继续拒绝。旧的一维 int64 捕获仍可读取。

网页增加可选实验方法 / 模型和数据集名称，经后台及独立 worker 透传，仅选择作者已有实验。它们不是论文依据，也不授权修改原训练协议。默认作者执行仍不启用严格前置关卡；严格不可用时记录原因并可继续普通作者运行。源码修复与严格核验继续互斥。

## 网页验收脚本

`scripts/verify_browser_pdf_holdout.py --strict-validation` 实际勾选网页严格核验，并核对后台收到的请求、固定来源与协议、完整作者运行、独立模型预测、正式核验结果和数值比较。实际 DOM 表格、保存结果、下载 Markdown / ZIP 及刷新后历史报告必须一致。作者日志或 `reference_only` 不能代替独立复算。

`--experiment-method GCN --experiment-dataset Cora` 经真实网页输入框选择实验。`--require-independent` 另外核对未使用论文资格，须配合 `--require-comparison` 或 `--strict-validation`；它本身不证明数值复现。

脚本分别记录普通完成、严格数值通过、完整核验但数值未达标、核验不可用及执行失败。严格模式允许将数值未达标记录为完整且准确的核验结果；核验不可用、证据缺失或运行失败均不算严格验收通过。观察期限结束不终止后台训练。

API 凭据只通过隐藏输入或 stdin 传入，不能写进命令行、源码、测试证据或归档。

## 任务收尾一致性修复（2026-10-23）

本轮发现并修复了一个实际状态缺口：后台曾在释放实验环境前记录 `FINISH / COMPLETED`。若随后清理失败，结果会变为 `ERROR`，但历史 ledger 和已保存报告仍可能显示完成。现在本地任务在环境收尾后发布终态，独立 worker 的 supervisor 在回收后追加最终记录；历史页面优先使用最新进度与最终结果，不沿用较早的成功状态。

报告增加一个可替换的“任务收尾”块，统一记录总任务状态、环境释放与错误诊断，并同步内存报告、报告长度、公开及运行目录 Markdown 和结果 JSON。历史报告重新生成也应用同一收尾信息，旧报告 revision 不会恢复旧的收尾结论。完整执行输出附件仍保留在报告末尾，ZIP 导出保持可读。Markdown 被占用等发布异常记为 `ERROR`；被锁的物理文件无法强行改写，内存报告及可写的 JSON 会记录保存失败，保留原证据。

总任务状态与实验数值结论分别保留：环境清理或归档失败不能伪装任务完成，也不会改写已有的 `paper_metrics_verified`、`is_reproduced` 或原始比较记录。报告、日志、模型、实际输入、划分和源码证据继续保留；本次实验环境、依赖和所属运行资源在终态收尾时释放，应用自身解释器不属于本次实验清理范围。

后处理相关定向回归完成 **237 passed / 3 skipped**，覆盖正常完成、清理失败、作者运行失败、worker 非零退出、取消及超时、历史终态、Markdown / JSON / ZIP 一致、旧报告 revision 和报告写锁异常。三项跳过需要专用原生依赖缓存，不计为通过；此批验证的是工程收尾机制，不是 tunedGNN 的真实完整训练、论文数值比较或最终源码全量验收。
