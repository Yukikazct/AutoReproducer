# 智能调查与排障

通用真实 PDF 复现表单默认开启“智能调查与排障”，默认采用 `collaborative`，沿用当前配置的模型；可关闭或选择单角色。直接 API 请求字段 `intelligent_recovery` 只接受显式布尔值，省略时仍为 `false`。选择其他输入方式时不会沿用上一项 PDF 任务的开关。开关经后台线程、独立工作进程和复现服务透传，不增加前置人工审核。

## 任务级协调与恢复证据

`Orchestrator` 从受管环境内的主流程建立一个 `RecoverySession`。独立调用仓库服务时自行建立，嵌套调用复用当前会话。论文识别、仓库发现、入口规划、环境准备、数据准备、作者命令和结果调查共享事实、未决问题和行动账本；切换角色、服务或错误不会重置额度。默认累计模型请求与 token 不设上限，仍共享 4 次主动检查、2 轮源码补丁和 8 次恢复动作。

`data.intelligent_recovery` 的 v2 记录包含 `goals`、`facts`、`unresolved_issues`、`phases`、`decisions` 和 `actions`；旧版 `tasks`、`reviews`、`usage` 保留。`data.recovery_summary` 提供剩余额度、已执行/已验证动作和仍需处理的问题。每项动作关联阶段、问题、来源证据、规则或角色审查、实际执行回执与验证结果。消息送达、模型建议和安装成功不能单独证明作者命令恢复。

恢复遵循“问题 → 原始证据 → 动作 → 审查/规则 → 执行 → 验证”。解析未完成时重新核对原 PDF 的页覆盖、表头和 URI 注释；仓库发现重新核对原文链接和用户地址。原 PDF 哈希变化时停止。入口规划依照实际校验错误补读固定源码并修正规划；源码补读计入共享检查额度。环境恢复沿用既有解释器选择、原生预检及受控依赖恢复。数据和硬件确实不可取得时保留具体阻塞，不改变作者实验。结果阶段沿用产物检查及已支持的独立复算路径。

实际环境与源码修改串行执行；无新证据的重复动作、取消、超时、回滚失败、进程清理未确认或额度耗尽会停止。严格数值模式保留原始源码冻结要求。修复副本原命令运行完成与原论文指标通过仍分别记录。

## v6 报告

正文先回答完成阶段、参考比较、独立核验、实际恢复效果及剩余问题，再展示本次冻结实验、统一指标表与恢复贡献。指标保留单位、数据划分、重复次数、差值及可比较性；未取得的值不填零。完整命令、日志、探针、源码补丁和哈希继续保存为校验附件。

`ReportViewModel` 只从结构化原始结果和确定性结论派生。实时报告、历史离线升级、网页、Markdown、ZIP 使用相同模型生成的正文。报告 v6 的历史升级不调用模型或训练，保留原始结果及报告；旧记录缺少恢复回执时显示“未记录”。

开启后可选择单智能体自检或多智能体独立反证审查。请求字段 `intelligent_recovery_mode` 只允许 `single`、`collaborative`，默认后者；关闭调查时清除先前单角色选择。模式经网页、后台线程和受管 worker 一直传到实际 `RecoverySession`，结果保留实际运行模式。

调查围绕实际失败展开，使用冻结源码上下文、作者运行环境元数据、明确公开的产物约定及原始作者断言等有限证据。工具拒绝路径逃逸、链接跳转、冻结哈希漂移以及未列入可读清单的数据；调查工具不执行作者训练代码。源码修改继续受原有修复权限和协议保护约束，调查开关本身不扩大可编辑范围。

`source_context` 可以按文件路径补读源码，也可以通过 `paper_pages` 选择原 PDF 页；页文本摘要须与冻结来源一致。实验理解保留方法/数据/划分/重复/单位等已知设置及缺口。局部契约首版支持同文件的纯函数和作者原有断言，用有成本上限的解释器检查；导入、模块初始化、装饰器及不支持的语法会明确拒绝。补丁审查期间，该工具可在内存中的候选函数上执行未改动的原断言，失败直接否决候选。它不会创建模型自定的 expected，也不将局部断言通过推断为完整数值等价。

`artifact_contract` 也能读取作者声明的逐步结果文件。JSON/CSV 保留公开结构与统计口径；NPY/NPZ 只解释有限 header，提供数组名称、声明的 shape/dtype 与首维数量，不加载数组、pickle 或逐行预测/标签。首维不同可以提示产物对应疑点，首维相同不能证明样本一一对应。当前单文件仍最多 2 MiB，NPZ 最多 64 个数组，单个 header 最多 64 KiB；超过边界明确拒绝，payload 完整性和数值正确性仍未验证。

公开产物清单显式声明 `metric_summary=true` 时，该工具可观察平铺 JSON 中有限的聚合指标 `metric/value` 及方法、数据、划分、统计、次数和单位。数值必须有限且非布尔值；数组、逐行目标/预测和无关内容不进入模型上下文。普通公开 JSON 不自动取得此授权，私有路径和哈希门禁继续适用。

默认不以固定模型请求总数或 token 总量硬切调查：`max_model_requests` 与 `max_tokens` 为 `null`。调查仍受探针、补丁和动作边界、取消与无进展停止条件约束；当前边界为 4 个探针、2 轮补丁、8 个动作，具体以本次保存的 `budget` 为准。没有供应商用量证据时记为 `unknown`，不按零用量推断。

结构化结果保存在 `data.intelligent_recovery`，包含版本、开关、运行模式、状态、冻结身份、预算、任务、用量、人工处理要求、停止原因和调查产物路径。每项任务保留触发原因、假设、探针与决策。`single` 和 `collaborative` 分别表示单角色与角色协作模式。

调查得到的原始检查结果同时提供给失败分析者与补丁审查者，两种模式使用相同观察。补丁审查者可以在剩余的共享检查预算内连续要求不同补查；重复同一检查会停止该候选。作者原有断言反驳候选时，控制器直接否决，不再由模型重新批准。已经拒绝的相同补丁不能通过改写理由或调整文件顺序重新送审。

`reviews` 保存每次实际审查的角色、阶段、候选内容摘要、运行身份摘要、证据引用与决定。候选相关的断言结果按候选内容隔离保存，后续候选不会继承上一个候选的失败或通过证据。下一轮修复能看到具体审查意见及其对应候选的检查结果；它们仍不授权改变原始命令或实验协议。`usage.roles` 分别统计调查、分析、修复和审查的模型请求、实际已知 token、缺失用量与耗时。

报告 v6 正文展示恢复贡献表和“智能调查与处理结果”摘要；完整调查快照保存在同目录的 `<report>_details.md`。详情链接绑定 SHA-256，下载包会核对附件哈希。ZIP 中的 `<report>.evidence.json` 同时保留结构化调查字段与共享展示模型，`<report>.manifest.json` 记录报告、详情及证据文件的字节数与哈希。

有审查回执的新结果增加一行“审查作用”，列出实际审查次数、请求补查次数和被否决的不同候选数；历史结果没有回执时不推算次数。这些次数是协作干预记录，不能替代 A/B/C 对照的收益结论。

历史报告重渲只读取保存的结果，不调用模型、不重跑调查或实验，不改写原始结果与日志。调查完成、修复完成、作者代码运行完成、论文参考对照和独立指标核验分别表达；智能调查状态不会将未核验的论文复现结论升级为成功。

真实浏览器验收入口支持 `--intelligent-recovery-mode off|single|collaborative`，默认关闭。`--allow-source-repair` 单独授权有界兼容性修复，不能与 `--strict-validation` 同时使用；开启调查本身不会开启源码补丁。验收会核对后台实际模式、修复授权和用量，并分别保存作者执行、参考比较、独立核验及严格数值判定。示例：

```powershell
python scripts/verify_browser_pdf_holdout.py --pdf paper.pdf --repo https://github.com/author/repo --freeze freeze.json --tag trial --intelligent-recovery-mode single --allow-source-repair
```

该命令仍需匹配运行中网页的数据根，并沿用隐藏输入提供 API 凭据；完整新论文准入另需 `--paper-id`、`--require-independent` 及相应比较/核验模式。兼容修复副本的成功不会升级为原始源码严格数值复现。

调查模型或格式错误作为辅助分析不可用保存；探针超时、取消和进程清理未确认属于运行停止条件，立即阻止后续修复。结果阶段发生这些停止条件时，保留既有作者执行与核验原始证据，报告暂不发布本次完成或论文复现成功结论。
