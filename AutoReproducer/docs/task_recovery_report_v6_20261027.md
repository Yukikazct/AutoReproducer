# 任务级协作恢复与报告 v6

本次实现让解析、发现、规划、环境、执行和结果调查共用恢复状态；报告从同一结构化展示模型生成，保留作者执行、参考比较和独立核验的不同结论。工程回归与自然案例收益分别验收。

## 实现

- 任务级会话保存冻结目标、持久事实、未决问题、行动及其审查和验证。嵌套服务共用 4 次主动检查、2 轮源码补丁、8 次恢复动作，模型请求和 token 默认没有累计上限。
- 解析或发现失败后，核对相同原 PDF 的页面覆盖、注释和用户仓库，进行一次有证据的修正。入口规划根据实际校验错误补读固定源码并重新规划；解释器切换、依赖恢复及兼容补丁进入同一账本。没有新证据的相同动作停止。
- 每次修改串行执行。安装或建议成功不等于作者命令恢复；实际重跑回执、验证、拒绝和回滚分别留存。取消、超时、进程清理未确认和预算耗尽阻止后续执行；延迟清理同步最终结果和报告。
- 普通真实 PDF 网页默认开启协作恢复，关闭和单角色仍可选择；直接 API 和 CLI 的原默认行为保持。
- v6 正文先给出完成阶段、参考比较、独立核验、恢复贡献和剩余问题，再列出统一指标及行动表。完整命令、日志、探针、补丁和哈希进入校验附件。缺少数值显示“未取得”，历史缺少恢复记录显示“未记录”。
- 历史升级是离线展示操作，保留旧报告，不调用模型或启动训练。网页显示同一模型生成的 Markdown，ZIP 同时保存展示模型和结构化依据。
- A/B/C 评测可接收独立评分器观察到的规划、完整执行和独立指标核验结果；组件未观察的阶段保持未知。C−A、C−B 和原有正式准入条件保持。

## 工程验收

验收覆盖：规划失败修正、连续不同错误、跨角色/阶段去重、共享额度、审查否决、原命令重跑、修复后数值未通过、取消、清理失败、回滚和历史报告升级。局部测试组有重叠，不把它们相加作为独立总数。

Windows Python 3.11/3.12 为主要 CI 验收组合，分别运行 locale 与 UTF-8 路径；macOS/Linux 运行兼容回归。新增 `Task recovery and report acceptance` 工作流，原生 CPU 工作流同时执行真实作者训练及独立核验的服务回归。最终测试数量及远端状态见本文件后续验证记录。

macOS 从 `AutoReproducer/` 运行全量回归：

```sh
TMPDIR=/private/tmp .venv/bin/python -m pytest tests/ -q -ra
```

使用规范临时路径避开 macOS `/var`、`/tmp` 的符号链接别名。原生训练测试还需要专用且版本匹配的 `AUTOREPRO_TEST_CPU_DEPS`，没有该缓存的跳过项不计为通过。
