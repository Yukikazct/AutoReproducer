## #59：停止后确认进程退出，覆盖 PDF 解析

真实后台任务在解析 PDF 和路由标题之前就进入所属 worker。解析器卡在原生调用中时，停止请求仍由外层持有者处理；协作停止超时后，通过本任务的 Windows Job 回收进程树。

Windows 的 `KILL_ON_JOB_CLOSE` 和 Job 活动进程数归零都可能早于单个进程的完整退出。收尾现在保留 Job 句柄，采集所属进程句柄，终止整个 Job，等待进程退出并复核 Job 内进程清单。查询、终止或等待失败时保留回收未确认的凭据；只在确认收尾后释放环境并允许重置。

真实子进程测试覆盖正常父进程退出、取消及后代进程；清理回调立即检查所有已观测后代的句柄已进入退出状态。另一项测试把实际 worker 的 PDF 解析器替换为阻塞的 Windows 原生调用，验证宿主不先解析、停止后 worker 与子进程退出、活动作用域归零，并可再次注册同一任务位置。

## #61：第二轮依实际失败补充文件，并保留首轮修复

自动修复每轮从最新实际 traceback 选择固定源码。第二轮可在原白名单内补充刚到达的文件，整个会话累计最多三个文件、最多两轮；不支持的错误、超出显式白名单或累计预算时停止模型请求。

失败候选会整体回滚，第二轮模型收到的仍是原始源码。模型上下文现在同时包含首轮与最新失败，明确要求重新提交完整补丁组，保留仍需应用的首轮兼容修复。原始源码、数据、命令及协议核对继续执行。

比较与报告回归同步验证差异诊断的额外一次模型调用、证据引用、诊断落盘及最终环境收尾信息。
