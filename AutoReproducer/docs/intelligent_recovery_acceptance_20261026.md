## 调用预算修订

按用户最新要求，默认 `max_model_requests=null`、`max_tokens=null`，不再按 8 次请求或 64k 累计 token 截断。所有恢复角色、补读、格式修正和重试仍共享用量记录。保留 4 次主动检查、2 轮源码补丁、8 次修复动作，以及取消、清理未确认和无进展停止条件。

供应商的单请求上下文窗口与本任务累计用量分别记录。测试已确认 12 次请求、超过 64k 的累计估算量仍可继续；缺失的实际 token 和费用保留未知。

## 关键验证边界

- 新检查证据影响下一次调查决策，独立反例可以否决补丁；原作者断言检查失败时直接否决候选。
- B 的同角色自检与 C 的独立审查使用相同工具和共享预算，切换角色或更换错误不重置预算。
- 原命令、原数据、训练与评测设置、容差保持冻结；缺少可信参考时数值等价保持未知。
- 调查工具拒绝任意排障命令、路径逃逸、私有评分文件、不可读文本及冻结哈希变化；原断言解释器限制操作、分配和递归成本。
- 原执行或探针清理未确认时保留阻断属性和回执；结果调查停止不会被吞为普通分析失败。
- 报告正文保留实验设置、结果、分析及简短调查摘要；长依据、引用和日志进入详情附件；历史重渲不启动调查。

## 正式验收缺口

`evaluation_complete=false`。目前没有登记为本轮正式 holdout 的 12 个自然新阻塞案例，也未完成 3 篇新论文的完整选定实验，因此不能声称达到净增 2 案例、接管需求降低 30% 或多智能体优于单智能体的目标。

默认可执行适配器已覆盖 Python API 兼容、本地导入、受限缺失依赖恢复及结果产物调查，具体边界见 `recovery_benchmark.md`。依赖路径尚不支持版本替换、原生兼容和解释器切换；结果路径目前只支持一个有界 JSON 聚合指标。自然案例仍必须来自至少 6 个未用于本轮调试的仓库，先登记原始失败、完整冻结输入与正确性判据，再执行 A/B/C 各 3 次。工具和组件支持不能代替正式样本验证。

已保存 TabM、Graph-MLP、TabPFN 等静态筛查材料。TabM 官方数据下载尚未成功；Graph-MLP 声明 Python 3.7/PyTorch 1.7，当前受管 Python 范围不支持该解释器；TabPFN 原版没有可直接运行的完整小例脚本。补充下载了 NOTEARS、DAGMA、pygcn 的固定源码和论文：NOTEARS README 将入口明确称为 demo；pygcn 明确声明不用于复现论文报告结果；这些材料未被冒充为完整论文验收。

正式论文评测需要冻结产品并登记未使用身份，执行原配置；需要产品修改时，将该论文转为回归样本，再重新冻结并更换候选。作者执行、参考比较、独立复算和严格数值验收分别记录。

## 回归记录

原生 CPU 服务回归为 **51 passed**（`test_intelligent_recovery_service.py`、`test_discovered_repository_service.py`、`test_strict_validation_service.py`）；局部契约与源码修复相关组为 **208 passed、3 skipped**；评测器、适配器及身份注册相关组为 **94 passed**。实际 CPU 夹具使用独立的既有精确依赖缓存，不在测试中重新安装训练依赖。

显式 220 个顶层测试模块的全量为 **4835 passed、180 skipped、1 warning**，耗时 939.41 秒。全量启动后另修正了评测器两条 Oracle 分支以及提交后 A/B 基线测试身份；这些更改以最终 focused 回归复核。缺失固定基线 Git 对象时，本地集成测试明确跳过，CI 明确失败；CI 拉取完整 Git 历史以执行真实旧版本对照。

更早的一轮全量为 4763 passed、180 skipped，仅保留为阶段记录。上述跳过不作为验收通过；本机原生 CPU 服务组单独执行了依赖充分时的真实路径。GitHub 新分支的跨平台结果另以其 workflow 状态为准。

## 后续启动与正式准入核验

Ubuntu 全量 CI 发现智能恢复参数归一化提前导入应用依赖，阻断纯标准库宿主向受管环境交接。参数处理已拆为共享标准库模块，覆盖前台/后台与关闭、单智能体、协作三种模式。本地启动与严格验证相关组为 **188 passed、3 skipped**；原先跳过的 3 项随后使用既有精确 CPU 缓存实跑，均通过。修复提交 `cf4e1ae` 的 Ubuntu Python 3.11/3.12 回归和四项原生 CPU job 已通过；后续提交的 CI 状态须单独核对。

正式恢复评测增加可信操作者的有界暴露审计、共享论文注册表快照和实际 Git 源码身份核验。历史结果仍可汇总，缺少正式准入证据时保持 `evaluation_complete=false`。独立反例验证发现的旧论文换 URL、同源多 URL 和布尔/整数混用问题已加保护；源码登记命令可从完整 checkout 生成文件与 Git blob 回执。它核验操作者取得的实际材料，不能自动证明未记录的历史使用或远端归属。

最终准入、benchmark 和 registry 联合组为 **122 passed**，包含源码路径解析越界前停止读取的检查；四类 adapter 兼容组为 **191 passed、1 skipped**，该跳过仅针对 Windows 不适用的 POSIX venv 链接。独立复核确认原先 14 个绕过变体均被拒绝。这些都是工程验证，不计作自然恢复收益，组间结果不相加。

ANODE 官方正文与附录、24 文件的完整固定 Git checkout 已取得，新的只读源码登记命令在该 checkout 上成功。ANODE、NGBoost 的协议筛查材料保存在本机详情目录；尚未启动正式论文实验或自然案例对照，也未因此增加正式验收成绩。12 个自然案例和 3 篇完整选定论文实验的缺口仍然保留。
