# 依赖环境管理

## 应用与测试依赖

`requirements.txt` 是应用依赖的唯一清单，包含网页、PDF 解析、文件锁，以及主进程直接使用的 packaging、NumPy 和 Pillow。`requirements-test.txt` 引用它，再添加 pytest 和测试绘图所需的 matplotlib。PyTorch、SciPy 等论文运行包仍按实验安装到托管环境。

```bash
python -m pip install -r requirements.txt
python -m pip install -r requirements-test.txt  # 开发与测试环境
python -m pip check
```

自动准备 CPython 3.11/3.12 时从源码位置读取同一份生产清单，安装与健康检查同步使用其版本要求，包含上限约束。恢复入口导入阶段只依赖标准库；缺少 packaging 等应用依赖时可以继续进入独立环境修复。测试依赖不会被自动安装到应用恢复环境。

## 论文运行环境

网页、CLI 和直接 Python 调用的复现入口均自动释放论文运行依赖。共享同一 `AUTOREPRO_DEPS_ROOT` 的任务从安装到报告、结果归档及清理结束全程串行执行，最多持有一套当前实验环境及其补装包。切换仓库候选或依赖清单时先释放上一套依赖，再安装新清单；不再跨任务保留多套 PyTorch 等论文包。

收尾顺序为：作者进程及其子进程退出 → 收集图表与证据 → 生成并保存报告、结构化结果 → 删除论文依赖和补装目录 → 写入清理回执 → 发布最终完成事件。安装失败、运行异常和可处理的中断同样进入清理。强制结束持有者进程后，下一次任务在安装前检查并删除遗留依赖；活动持有者未退出时，其他任务等待同一操作系统文件锁。

清理失败会保留具体路径和原因，将本次最终结果标为 `ERROR`；残留未能删除时拒绝创建下一套环境。`data.environment_cleanup` 保存删除清单、释放字节数、残留及错误，固定预设与作者仓库的运行目录另外保存 `environment_cleanup.json`。报告、图表、日志、数据和源码证据继续保留。

AutoReproducer 自身正在使用的应用 Python 及生产依赖继续保留；不会卸载宿主 Python 或用户的开发环境。作者训练使用的托管隔离 Python、为它下载的解释器、uv 工具和下载缓存随实验释放，切换训练版本前先清理上一套托管环境。应用自动恢复下载的 wheel、pip 缓存和 Python 安装程序在复现结束后删除。论文包安装设置 `PIP_NO_CACHE_DIR=1`，避免新增下载副本；不会清空用户其他程序共用的全局 pip 缓存。后续任务需要重新安装论文包，因此离线任务不能依赖上次运行留下的环境，`--prepare-environment` 也只准备和记录本次环境，结束后照常释放。

PDF 作者仓库入口启用依赖版本和导入健康检查；固定预设仍按各自配置决定是否启用，当前仓库预设设置 `dependency_health_check=False`。应用自身的兼容 Python 与生产依赖检查保持开启。自动释放独立于此开关，也不依赖容量配额或缓存年龄。

兼容 Python 的工作进程异常退出时，父进程在确认其进程树已经结束后兜底回收；若父进程缺少文件锁依赖，则交给已验证的兼容解释器执行同一套回收。另一任务已取得缓存锁时不会删除它的环境。应用环境准备失败或中断时，也清理已下载的 wheel、pip 缓存和安装程序。

通用 Docker 路线使用带任务所有权标签的临时镜像和独立 Buildx 构建器，不再保留共享实验底座。构建结束立即移除构建器、卷和本次下载的 BuildKit 镜像；报告保存后移除实验镜像、容器及持久工作区中的 `.autorepro_deps`、`.autorepro_tmp`。进程意外退出后，下一任务依据依赖根下的 `.autorepro-docker.json` 回收；回收失败时阻止新环境创建。旧版本的固定 `autorepro-env:latest`、`autorepro-base:latest` 在创建新实验镜像前释放。这条路线需要 Docker Buildx；既有外部镜像和其他项目的构建缓存不做全局清空。

### macOS 与 Windows/Linux 的安装包版本

作者仓库的依赖规划、安装校验和运行时缺包修复共用 `src/dependency_versions.py` 的版本选择。macOS 使用 `torch==2.5.1`、`torchvision==0.20.1`、`torch-scatter==2.1.2`、`torch-sparse==0.6.18`；Windows/Linux CPU 构建保留对应的 `+cpu` / `+pt25cpu` 后缀，CUDA 构建保留 `+cu121` / `+pt25cu121`。Neural ODE 的固定 CPU 预设采用相同的 PyTorch 选择规则。

macOS 图计算包仍从 PyG 的 `torch-2.5.0+cpu.html` 索引获取；索引名中的 `+cpu` 不代表 macOS wheel 的版本也带有该后缀。运行时首次缺少图计算扩展时，也会补上对应 wheel 源。macOS 不支持 NVIDIA CUDA，作者仓库计划要求 CUDA 时会明确报错，不会静默改成 CPU 或 MPS。

Apple Silicon / Python 3.12 的 GPRGNN 依赖已通过真实安装与张量、稀疏矩阵、图卷积检查；这不等于论文训练完成，也不覆盖 Intel Mac 或任意依赖组合。旧的失败记录保留，论文依赖在本次任务结束时自动释放。

## 保留实现：健康检查与增量复用

健康检查中的条件依赖（PEP 508 marker）由所选训练解释器实际判断，涵盖 `python_full_version`、实现及平台条件，不借用应用 Python 的环境或版本提示。这样应用和训练使用不同 Python 时，不会漏查实际需要的版本，也不会因不适用的依赖误触发重建。

版本与导入健康检查可以在当前环境安装后使用。以下跨清单和跨任务的缓存复用机制保留给单独调用底层依赖执行器、且启用 `dependency_health_check` 的调用路径。完整复现入口使用上述自动释放策略，不启用跨环境的增量共享，也没有网页开关可开启它。

1. 优先使用原清单的就绪环境，检查包版本、实际导入位置及原生运算。
2. 在同一 Python ABI、系统、架构与下载源策略下，查找包含相同依赖要求的已验证环境。满足要求即可直接复用，包括离线运行。
3. 需要新增包时，使用 pip 的 `--dry-run --ignore-installed --report` 解析完整 wheel 依赖闭包。按实际安装元数据比较版本，选择可复用的基础环境；只安装缺少的 wheel，每个 wheel 使用解析得到的 HTTPS 地址与 SHA-256。
4. 增量目录记录基础环境引用、完整解析版本、共享包与新增包。执行和独立评价按“增量目录 → 基础环境”导入；健康检查核对完整解析版本，拒绝以宿主全局包补足缺失依赖。

基础环境保持原样，增量安装不修改其中的包。不同版本可以在增量层覆盖，原有基础环境及使用它的其他任务保持各自的版本。增量组合无法通过原生健康检查时，保留原因并尝试独立安装原清单。该增量复用实现覆盖普通 wheel 清单与已支持的公开 PyTorch 补充索引；私有源、源码地址、extras、marker 和嵌套清单保持原独立安装行为。

## 空间与回收

完整复现任务默认在开始前和报告保存后自动释放，不受下列配额、年龄和最近环境保护条件限制。下面的 CLI 仍可手动处理历史缓存；单独调用底层依赖执行器时，取得缓存锁、安装前及安装／执行正常结束、失败或取消后均会按同一策略维护。缓存命中也会触发，且不依赖健康检查开关。

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| `AUTOREPRO_DEPS_ROOT` | 数据根下的 `deps/` | 依赖缓存位置，可改到其他磁盘；数据根由 `AUTOREPRO_DATA_ROOT` 指定，默认是项目 `data/` |
| `AUTOREPRO_DEPS_QUOTA_GB` | 20 GiB | 历史缓存和底层执行器维护的容量目标 |
| `AUTOREPRO_DEPS_MIN_FREE_GB` | 2 GiB | 缓存所在磁盘的最低可用空间目标 |
| `AUTOREPRO_DEPS_INSTALL_RESERVE_GB` | 2 GiB | 新安装下载、解压和复制的额外空间预留；这是可配置策略，不是包体积预测 |
| `AUTOREPRO_DEPS_KEEP_DAYS` | 30 天 | 历史缓存和底层执行器维护的闲置保留期 |
| `AUTOREPRO_DEPS_KEEP_RECENT` | 2 | 维护时保护最近使用的就绪环境数；设为 0 可取消，完整复现收尾不采用此保护 |

配额维护先处理失败或未完成的环境，再按最后使用时间处理闲置环境。安装和作者命令执行使用同一缓存锁；外部清理遇到活动任务直接跳过。统计覆盖各 Python／平台目录、补装包和增量环境，保护在用环境及完整基础环境引用链。增量环境仍引用的基础目录不能单独删除；同时选择增量与基础目录时先删除增量目录。超过闲置保留期的环境也会进入回收候选。

pip 下载、解压和缓存统一放在依赖根的 `.pip-temporary/` 所属目录，安装子进程返回并完成清理后释放。单独调用底层执行器时，异常终止的安装临时目录在后续维护中检查归属和锁，满 24 小时后回收；完整复现入口还会在取得独占锁后清理遗留实验环境。不会删除其他应用的系统临时文件。安装前要求磁盘余量达到最低余量与额外安装预留之和，大型 CUDA 环境可调高预留。

损坏的最后使用时间回退到目录修改时间，基础环境引用统一按跨平台路径规则解析。遇到符号链接或读取失败而无法完整计量的环境会保留，同时保护其已知基础环境；回执通过 `errors` 和 `unmeasured_environments` 列出问题，此时 `remaining_bytes` 仅包含成功计量的目录，`quota_satisfied` 为 `false`。容量、空间与保留期必须有限且非负，最近保留数量必须为非负整数；自动维护的 `AUTOREPRO_DEPS_QUOTA_GB` 还必须大于 0，非法参数会在回收前报错。维护记录列出删除／保留原因、文件字节数和维护前后磁盘余量；在用、被引用或最近保留的环境使容量仍超限时会明确记录原因，CLI 返回 2。

容量目标只约束可回收缓存；仍被保留环境引用的基础包可能使缓存暂时超过目标。最低可用空间目标不能保证任意大小的未知依赖或训练产物都足够。PDF、真实数据、模型产物、运行日志和报告不在这项回收范围内。完整复现入口的下载缓存处理见上文自动释放规则。

```powershell
python scripts/resource_cli.py deps-prune                       # 预览
python scripts/resource_cli.py deps-prune --yes                 # 执行
python scripts/resource_cli.py deps-prune --cache-gb 12 --min-free-gb 4 --yes
python scripts/resource_cli.py deps-prune --keep-recent 0 --yes # 取消最近环境保护
```

网页历史记录中的依赖表显示缓存目录占用、容量目标、当前磁盘余量、最近维护结果，以及已有增量环境的基础引用。运行证据中的 `dependency_paths` 包含实际使用过的全部依赖目录，完整复现收尾后这些目录可能已释放；`environment_cleanup` 记录最终释放结果。底层缓存路径的 `dependency_reuse` 记录共享与新增包，`dependency_cache_maintenance` 记录相应维护清单与磁盘检查结果。
