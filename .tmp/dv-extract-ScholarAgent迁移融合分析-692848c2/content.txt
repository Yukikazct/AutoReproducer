[html:l36] 核心判断： ScholarAgent 与 AutoReproducer 属于 同一课题域（论文自动复现 + 多智能体 + 沙箱执行 + 预算受限） ，技术路线高度重合，但侧重点不同 ——

[html:l46] 三条最重要的发现
[html:l48] 优化闭环（UCB→BeamUCT+经验先验）可无缝升级： AutoReproducer 已有 UCB1 方向调度与 RealSimulator 的 Keep/Reject 真实闭环，ScholarAgent 的 BeamUCTSearch （参数树 UCT + Beam 宽）与 ExperienceStore （跨论文经验 JSONL + 先验播种）是纯增量补强，不破坏现有护栏（max_trials、LLM 调用预算）。
[html:l49] 验证可信度层是最值得融合的部分： AutoReproducer 的 Prompt-Free 验证负责「质量合规」，ScholarAgent 的证据链（Claim/Criterion/Evidence + SHA-256 锚定 + 确定性裁决门控）负责「可追溯与防篡改」 —— 两者正交，可叠加：迁移后「无真实执行证据一律不判 verified」的硬规则直接强化 L1/L2 的验收可靠性。
[html:l50] 「补丁安全策略」是当前最薄弱、迁移成本最低的一环： AutoReproducer 的 safety/patch_policy.py （99 行）相对 ScholarAgent 完整版（197 行）缺少目录级禁改模式、禁改扩展名（数据/权重）、文件名正则、单文件体积预算 —— 而这一层直接决定优化闭环「不会作弊地改掉评测代码/数据集」，属于 P0 必修 。

[html:l123] 4 核心机制逐层解析
[html:l126] 4.1 调度引擎（graph/engine.py + state.py + store/plan_store.py）
[html:l128] 图结构： START → router →(条件边)→ Send(execute_task)×N → router … → finalize/done → END 。state 用带 reducer 的通道承载 tasks/artifacts/events，支持并行节点安全合并更新。
[html:l129] router 六职责： ①就绪提升（依赖 COMPLETED 且 required_artifacts 齐备 → PENDING→READY）；②预算/审批门禁（未批准/超时/超尝试次数 → 停发或 finalize）；③串行互斥（serial 节点独占本 superstep）；④并行槽位（parallel 节点按 priority 排序取 max_concurrent 个）；⑤任务租约（execution_id + lease_owner + lease_expires_at）；⑥执行纪元（execution_epoch 防陈旧结果）。
[html:l130] execute_task： asyncio.wait_for 超时 → FAILED；执行返回前重读 store 做陈旧守卫，lease/纪元不符则丢弃并广播 task_result_discarded ；失败且 run_count ≤ retry_limit → 回 PENDING 重试，否则 FAILED 并沿 control/data 边 DFS 将全部后裔置 BLOCKED（ 失败级联阻塞 ）。
[html:l131] finalize： 死锁检测（无就绪节点且非全终态 → plan_failed）；预算超限/取消 → 取消其余节点；否则按是否存在 FAILED/BLOCKED/CANCELED 判 completed/failed。
[html:l132] Checkpointer： AsyncSqliteSaver（thread_id=plan_id）+ 进程内快照事务读改写；进程重启后 recover_interrupted_plans() 把 IN_PROGRESS 计划重置为 PENDING（清租约、保留已完成节点），发 plan_recovered 事件 —— 这是 AutoReproducer 完全缺失的「断点续跑」能力。
[html:l137] 4.2 规划层（intent/classifier.py + planner/planner.py + agent_planner.py）
[html:l139] 意图分类： _classify_parallel 用 asyncio.gather 并行发 3 个独立 LLM 调用（意图分类 + 查询改写 + 论文检索字段抽取：paper_title/arxiv_id/search_query/method_name），各自降级；无 Key 或 JSON 非法时回退确定性正则（复现/对比/代码执行/自研，抽取 arXiv id、GitHub URL、commit SHA、框架列表、smoke/full 标记、ablation/plot/fix 标记）。
[html:l140] 六类模板计划： 论文复现（parse → 冻结 Claim Rubric → repo_discovery → 消融设计(可选) → prepare → resolve → runtime → install → 有界调试执行 → 对比 → fix/plot(可选) → 主张证据图）；框架对比（调研 + 每框架并行 generate/run）；代码执行；自定义 Benchmark（audit → 防泄漏切分 → 冻结指标契约 → 生成适配器 → 两段执行 → 隐藏验证）；AutoResearch（冻结 spec → 试验循环 → holdout 验收；数据集版走 ToT 消融）。节点带 contract（allowed_tools/输入输出 artifact），边分 control/data 两类。
[html:l141] LLM 规划代理 + 校验回退： 输出 {nodes:[{ref,name,type,assigned_to,deps,artifacts}]} → 归一化（Agent 白名单、task_type 关键词映射、伪模式补 artifact 缺省）→ 物化 TaskNode → 按 _CANONICAL_NODE_CONTRACTS 与意图必需节点校验，任一失败整体回退模板（丢悬挂 artifact、环检测）。
[html:l146] 4.3 专业 Agent 层（agents/）
[html:l148] Librarian： 文献分析； claim_rubric_extract 把论文冻结为 ≤16 claims × ≤6 criteria 的分层 Rubric，附 canonical_rubric_sha256 冻结，下游先验哈希校验防篡改。
[html:l149] Data： ablation_design 有界 ToT（候选 LLM → 评估 LLM → score = mean(information_gain, relevance, reproducibility) − 0.25×risk → 排序剪枝）； claim_evidence_build 按冻结 Rubric 与 authentic 执行证据构建主张-证据图。
[html:l150] Coder： 静态依赖解析（AST import + requirements/env.yml/pyproject，std-lib 过滤、py39 版本钉归一化）； pip 自愈 ≤3 次 （LLM 给 remove/replace/rewrite/upgrade_python 或规则回退）；运行时缺模块自动补装；按 pyproject requires-python 升级沙箱镜像。
[html:l151] ResearchCoding（论文复现核心）： 有界调试 ≤3 次运行、≤2 次 LLM 修复 （每轮失败且 repairs_used<2 才打补丁）；补丁前备份原文件、仅允许改已有文件且过 PatchPolicy；每轮前后对整个 workspace 的 .py 做 SHA 指纹 ，运行中被篡改即中止并恢复；全失败 restore_backups 回滚。AutoResearch：冻结 spec → Harness 试验循环 → best → holdout 验收。
[html:l152] Benchmark（纯确定性、无 LLM）： 数据审计（列统计/重复检测/映射自动识别，弱信号或平局拒绝猜测）；防泄漏切分（hash/random/group/time 四策略；test/preflight 只留特征 + __benchmark_id ， 隐藏标签存后端私有目录 ，写后重读断言无目标列且 id 集合一致）；冻结指标/奖励契约（后端复算）；隐藏验证按 id join 复算指标并报告覆盖率。
[html:l153] repo_ops（确定性绕过 LLM）： 发现链 = 用户 URL → Papers with Code(HF) → GitHub 搜索 → curated 回退；prepare = 缓存 → 浅克隆 → git init/fetch → pin revision 校验；入口文件打分 + 复现模式决策 （auto → 生成 120s 预算的 smoke runner；full/smoke 分级）。
[html:l158] 4.4 研究闭环（research/：harness.py + spec.py + patch_policy.py + workspace_snapshot.py）
[html:l160] 冻结契约： ResearchSpec （frozen dataclass）一次性物化并 sha256：eval_command、metric_key、direction、editable/protected_files、holdout_command、min_delta、target_score、max_trials(≤20)、max_wall_seconds、eval_repeats(≤5)；任何 trial 中不可变。
[html:l161] 闭环流程： freeze spec → 基线评估（baseline 无效即终止）→ 循环：候选生成 →（候选永远基于当前 best 快照）restore best 快照 → apply → 多重评估 → improves() 判定（超 min_delta 才 Keep）→ Keep 则捕获新快照、Reject 则回滚 → TrialLedger 逐条记录 → 结束后恢复到 best 状态 → 隐藏 Holdout （只对最终 best 状态运行，多轮取 mean，要求 exit 全 0 且达 target）。
[html:l162] 补丁安全策略（patch_policy.py）： 目录级禁改模式（eval/test/data/benchmark/gold/label/verifier/checker…）、禁改扩展名（csv/tsv/jsonl/parquet/pkl/npy/h5/db/pt/pth/safetensors/bin…）、文件名正则（test_*/eval_*/dataset_* 等）、单文件 ≤96KB、editable 白名单 glob、路径穿越/符号链接防护、每候选 ≤3 文件；拒绝项返回结构化 PatchDecision 记录进 Ledger。
[html:l163] 快照： capture/fingerprint(sha256)/restore，Best-state 全程可由 SHA-256 追溯。
[html:l168] 4.5 优化器（research/optimizer/：ucb.py + beam_uct.py + experience_store.py + coordinator.py + policy.py + retrieval_adapter.py）
[html:l170] 双层搜索： UCB1 选「研究方向」（method/hyperparameter 等 arm，未试先选，支持 seed() 注入历史先验伪拉次与 retire() 退役）； UCTSearch 对每个方向维护一棵参数树（每层 = 一个超参，未试值先扩展，UCT 分数探索/利用，评估结果沿路径回溯）； Beam 保留 top-width 配置； BeamUCTSearch 门面把三者绑定。
[html:l171] ExperienceStore（经验库）： 每次 已验证 （真实评估非猜测）的试验追加 JSONL（repo/direction/params/metric/score/validated/context），上限 10k 条截断；提供 all/best/summarize； 先验播种 在启动时回放：direction_priors 喂给 UCB seed()，select_candidate 按上下文匹配挑出历史最佳配置作首个候选。
[html:l172] ExperimentCoordinator： 批量 propose（≤4 并行，eval_command 含 {candidate_config} 占位符则每候选独立配置文件并行跑，否则串行 candidate.json）；结果回馈 UCB/UCT/Beam/ExperienceStore；收敛条件（预算/墙钟/target/空间耗尽）；结束对 best 跑隐藏 Holdout（validation_runs 次，报 mean/std/target_ok）；输出结构化 LEDGER v2（含 UCB state、最终 best、experience_summary）。
[html:l173] 内置适配器（retrieval.v1）： 无需仓库代码即可做检索实验（角色识别 + BM25，ndcg@k/MRR/precision@k/recall@k，cutoff 截断）—— 一种「无代码候选评估」的插件模式。
[html:l178] 4.6 证据链（evidence/graph.py）—— 确定性裁决，绝不委托 LLM
[html:l180] 证据注册表：从真实 artifact 构建（非 LLM 声明），每条带内容 SHA-256 + authentic 判定：只有 run_metrics/rerun_metrics 中 status=completed 且 metrics 非空才视为「真实执行证据」。
[html:l181] 裁决门控：criterion 只有引用了至少一条 authentic 执行证据才允许 verified/partially_reproduced/contradicted；「进程退出码为 0 不能证明任何主张」。模式天花板：smoke 模式顶格 smoke_verified，未知模式顶格 partially_reproduced；无任何执行证据且存在资源缺失报告 → blocked_by_missing_asset（诚实降级）。
[html:l182] 产物：Claim→Criterion→Evidence 三层图谱 + 全图 graph_sha256，供报告与审计直接消费。
[html:l187] 4.7 沙箱与计量（docker-sandbox/ + usage.py）
[html:l189] 独立容器服务进程（默认 :8082），REST 创建持久会话（Bearer、 dk- 前缀 id）+ NDJSON 流式执行 + artifact（含图片 base64）返回；计划终态统一清理会话。
[html:l190] 安全加固清单：镜像白名单（精确/repo 匹配）、cap_drop ALL、no-new-privileges、可选只读 rootfs + /tmp tmpfs(noexec,nosuid)、可选非 root、CPU/mem/pids 限额、bridge 网络、挂载路径强制位于 WORKSPACE_ROOTS。

[html:l340] 7.1 总体策略与融合原则
[html:l342] 补位不替代： ScholarAgent 组件作为「增强层」并入 AutoReproducer 现有流水线，不推翻现有 8 Agent 状态机与存储体系；验证口径、验收指标（L1≥60%、2 篇升级）保持不变。

[html:l344] 护栏继承： 所有迁移的搜索/闭环组件都必须跑在 AutoReproducer 既有护栏内（max_trials=10 优化预算、方案级 100 次 LLM 调用上限、L0 配额）。

[html:l454] 9 风险与边界
[html:l456] 风险项 说明与应对
[html:l457] LangGraph 依赖重（P2） 引入 langgraph/aiosqlite/async 栈与现有同步流水线并存成本高，须做适配层并使 mock 模式全绿；P2 门前不触碰主线，避免「为架构而架构」。
[html:l458] 裁决门控改变现有验证语义 证据链的 unverifiable/blocked_by_missing_asset 会改变 ResultValidator 现有 pass/fail 口径，若直接替换会影响 L1≥60% 验收统计。融合策略：证据链作为 新增审计 artifact 并行产出，验收口径迁移期双轨统计，确认一致后再切换。
[html:l459] 冻结 spec 与 L1 浅复现的张力 冻结评测契约在「动代码不动评测」场景无副作用；但 L1 冒烟模式可能移动/裁剪文件触发 protected 规则。应对：editable_files/protected_files 白名单随复现级别预置（L1 最小集、L2 放开），并在 patch 决策中记录原因。
[html:l460] 防泄漏切分与「1% 子集」策略联动 若 L1 冒烟用随机子集且不加种子，跨复现不可比。应对：统一用 确定性 hash 切分 （按 id hash 取子集），子集由数据集注册表标准化登记，Benchmark 防泄漏切分器与注册表共用同一实现。
[html:l461] 经验库跨论文复用噪声 Jaccard 上下文匹配粒度粗，可能把不相关论文的经验当成先验。应对：先验仅作用于「方向级 UCB seed（伪拉次）」与「参数是否在搜索空间内」两点，任一不匹配即丢弃；经验记录必须带 validated 标记与数据集指纹。
[html:l462] 量化存储不适用于精确数值复现 沿用此前结论不迁移 FP16→INT8 到复现比对链路；量化仅保留为 L3 专家模式的体积压缩可选。
[html:l463] 许可与代码来源 ScholarAgent 为 MIT，可自由迁移，但需在新增文件中保留版权声明并记录来源路径；不迁移其前端整体（避免引入 Vue 构建链）。
